# CRUD de imágenes (BLOB) con Spring Boot, React y JWT

**Tema:** Mascotas · **Campos:** `nombre`, `raza` · **Foto:** `bytea` en PostgreSQL

Aplicación full stack con registro e inicio de sesión mediante JWT para administrar una colección
de mascotas. Cada registro guarda su fotografía como binario (`bytea`); el listado devuelve solo
metadatos y React descarga cada imagen como `Blob` para mostrarla con una Object URL.

## Estructura

```
taller_jwt/          Backend Spring Boot 3.5.7 · Java 21 · PostgreSQL
mi-proyecto-jwt/     Frontend React 19 · Vite 7
db/                  Scripts SQL
scripts/             Arranque del backend y del frontend
capturas/            Evidencias del funcionamiento
```

## Requisitos

- JDK 21 o superior
- Node.js 20 o superior
- PostgreSQL 18

Maven no hace falta instalarlo: el script de arranque lo descarga la primera vez si no lo encuentra.

## Configuración de la base

La contraseña de PostgreSQL se lee de `DB_PASSWORD` o de `PGPASSWORD`; no está escrita en el código.

```powershell
.\scripts\configurar-clave.ps1
```

Para usar otro usuario, puerto o base:

```powershell
$env:DB_USERNAME = "postgres"
$env:DB_URL = "jdbc:postgresql://localhost:5432/mascotas_db"
```

La base `mascotas_db` se crea sola al arrancar el backend si no existe, y Hibernate crea la tabla
`mascotas`. También se puede crear con `db/01_crear_base.sql`.

## Ejecución

```powershell
.\scripts\run-backend.ps1     # http://localhost:8080
.\scripts\run-frontend.ps1    # http://localhost:5173
```

En el navegador: `/registrar` para crear un usuario y luego `/gestion` para el CRUD.

## API

Todas las rutas de datos requieren `Authorization: Bearer <token>`.

| Método | Ruta | Cuerpo | Respuesta |
|---|---|---|---|
| POST | `/auth/registrar` | JSON `{username, password, rol?}` | `201` |
| POST | `/auth/login` | JSON `{username, password}` | `200` `{token, username, rol}` |
| GET | `/auth/items` | — | `200` lista de metadatos |
| GET | `/auth/items/{id}` | — | `200` · `404` |
| GET | `/auth/items/{id}/foto` | — | `200` bytes de la imagen |
| POST | `/auth/items` | multipart: `nombre`, `raza`, `foto` | `201` |
| PUT | `/auth/items/{id}` | multipart: `nombre`, `raza`, `foto` opcional | `200` |
| DELETE | `/auth/items/{id}` | — | `200` `{mensaje}` |

La foto es opcional en el `PUT`: si no se envía, se conservan los bytes y el `mime_type` anteriores.
Validaciones: nombre de 2 a 80 caracteres, raza de 2 a 120 e imagen `image/*` de hasta 5 MB.

## Base de datos

```sql
CREATE TABLE mascotas (
    id        integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    foto      bytea NOT NULL,
    mime_type varchar(100) NOT NULL,
    nombre    varchar(80)  NOT NULL,
    raza      varchar(120) NOT NULL
);
```

`db/02_consultar_mascotas.sql` contiene la consulta que muestra el tamaño y el contenido hexadecimal
del campo `foto`.
